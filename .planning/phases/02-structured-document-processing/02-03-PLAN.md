Make resource bounds enforceable before invoking the validator: cap schema/instance bytes and depth, reject cyclic local-reference expansion or expansion/composition cost exceeding a conservative documented work limit, and retain bounded Go-regexp semantics. Do not claim a timeout by abandoning an uncancellable validation goroutine. Test accepted local compositions and deterministic rejection of excessive branching/reference expansion; a policy/resource-limit error must be explicit, not a partially validated success.
Use github.com/santhosh-tekuri/jsonschema/v6, whose primary README documents draft 2020-12 support and exact-number-capable validation. Select/pin a maintained compatible release during implementation and keep its license notices. Choose JSON Schema 2020-12 explicitly; support local fragment references and bundled metaschemas, with a loader that rejects HTTP, filesystem and arbitrary external identifiers. Bound schema/document bytes, depth/complexity and compile/validation work; reject unsupported dialects/vocabularies rather than ignore them. Decode numeric instances as json.Number and preserve exact decimal/integer comparisons. Use the validator in process, not its network-enabled CLI. Cover nested refs, recursion traps, oneOf/allOf/not, arrays, additional/unevaluated properties, nullable values, enums with type distinctions and integers beyond float-safe range. Verify a referenced HTTP listener/sentinel file is never accessed.

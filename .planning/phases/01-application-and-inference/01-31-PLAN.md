  <action>
Implement explicit per-process active upstream, queued request and queued-byte bounds using existing Go synchronization patterns; keep tenant/actor sublimits and map state bounded. Charge queued/body bytes before large buffering, including unknown/chunked content lengths, and keep request/input/event limits distinct. Tie an execution permit to the closeable response/stream, not the moment headers return; all error/cancel paths release exactly once. Propagate client/worker shutdown to queued and active child work. Do not hold an outer upstream permit while awaiting child embeddings/model calls; bound internal fan-out separately so nested work cannot deadlock the same pool. Reserve bounded management capacity so cancellation/read/delete is not starved behind every active model stream or blocked by ordinary inference budget exhaustion. Reuse bounded pre-auth rate limiting without storing unbounded attacker-chosen keys/raw secrets; authenticated limits use current tenant/actor identity. Reject overload explicitly rather than silently queue forever or retry elsewhere. Add barrier-controlled tests for max active work, queued bytes, fair opportunities, early header return, abandoned bodies, disconnect, nested fan-out and control-call progress.
  </action>

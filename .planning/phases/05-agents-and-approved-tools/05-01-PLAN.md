Keep the existing assistant/prompt concepts and PostgreSQL records, replacing global list/get/external-ID lookups with tenant/owner/audience-qualified operations. Configuration selects approved model/routes, instructions, collections and built-in tool IDs; caller authority is intersected on every use, never replaced by assistant-owner privileges. Ignore client-provided authority/provenance fields. Preserve the original message text separately from derived model context and do not overwrite one with prompt-expanded text. Implement queued/running/succeeded/failed/cancelled/unknown run state using the core durable-job/fencing primitives. Persist model/tool attempts and enforce a concrete maximum turn count, tool calls, context/input/output bytes and wall time; derive resource limits from the shared service configuration rather than an unbounded recursive loop. Implement built-in knowledge.search/evidence.read through the real rag/source resolver and extract.submit/status through the real extraction/job service. Validate arguments with the local schema validator; extraction submit returns the actual job ID/state for later status queries, not a polling wait hidden in the tool. Carry evidence IDs and restriction unions into the next turn. Cancellation propagates to child calls and prevents fenced publication; a possibly accepted side effect is persisted as unknown and never replayed automatically after lease loss. Add tests for actual result/state/error semantics, bounded loops, source revocation between turns and duplicate/stale worker attempts rather than mock forwarding echoes.

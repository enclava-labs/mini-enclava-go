# Shared implementation contracts

These are engineering boundaries for the confirmed scope in PROJECT.md, not a separate design/approval phase. Each executable plan must implement and exercise its portion. There is one implementation of each boundary; do not add compatibility adapters or alternate runtime backends.

## Package ownership and composition

- Keep `cmd/enclava/main.go` as the one application composition root. `internal/httpx` owns HTTP/session/UI presentation, not independent inference or billing policy.
- Replace `internal/store/sqlite` with concrete PostgreSQL repositories in `internal/store/postgres`. Reuse service-local repository interfaces rather than creating a generic backend framework. Put fresh-schema SQL under the new store. No old-database import commands or dual writes.
- `internal/auth`: principals, credentials, sessions and application-resource permissions. Services do not invent `IsAdmin: true` or use API-key ID zero as system authority.
- `internal/source`: canonical source/object/version/document/block/span/chunk/profile types and `source.Authorizer` in `authorize.go`. Source authorization stays independent of parser and vector-store types; do not create package cycles. Repositories implement narrow interfaces owned by their consuming services. Use `source.ChunkProfile`, not a duplicate extraction DTO.
- `internal/artifacts`: durable original/result bytes and isolated scratch lifecycle, with opaque server-generated identifiers. A database reference is not permission to expose a filesystem path.
- `internal/jobs`: durable operation state, idempotency, worker leases/fencing and cancellation. Use PostgreSQL, not a second queue service.
- `internal/llm`: endpoint-specific transport and verified confidential transport. `internal/inference`: the shared authorized execution, accounting, routing and admission boundary around those transports.
- Reuse `internal/extract`, `internal/connectors`, `internal/rag`, `internal/chatbot` and existing prompt/template/module patterns for their selected responsibilities. Existing implementations are incomplete and must not retain their old bypasses just because they compile.
- Feature HTTP registration uses the existing Go ServeMux/module pattern. There is no plugin framework. The core application and extraction jobs start and work without Qdrant or configured connectors; only knowledge-dependent operations require the index.
- Feature plans own their leaf packages/templates/assets. One integration owner serializes changes to `main.go`, `httpx/app.go`, shared navigation, `go.mod`, `go.sum` and the existing application reference `docs/go-rewrite-contract.md`. Parallel feature tracks merge additive registrations without replacing another track's wiring. Do not run two writers against those shared files.

## Identity and storage

Every durable resource has a tenant and an owner or explicit audience. Every service operation receives a validated `auth.Principal` containing tenant, authenticated actor, credential/session identity, effective permissions and any delegated actor/billing subject. Do not accept those authority fields from an ordinary request body. A worker freezes the initiating identity and rechecks the relevant current authorization before privileged execution/publication.

Pre-authentication key-prefix candidate lookup and unique session-token-hash lookup are the narrow exceptions to tenant-scoped repository access. Verify the secret, expiry/revocation and stored actor before accepting that row's tenant; never substitute a default or request-asserted tenant. Subsequent operations remain tenant-scoped. `AllowedEndpoints` contains inference endpoint IDs, not HTTP paths; HTTP routes use permissions/scopes. Every resource allowlist—models, extraction templates, chatbots, agents, endpoints and IPs—has its matching explicit `All` flag plus item map. Only valid stored `mode:all` sets that flag. Absent, malformed and empty-list grants deny; an empty map alone never means unrestricted.

Local account enrollment is administrator-controlled; do not invent public signup, email delivery or account-recovery products. Store passwords with an established password-hashing implementation. OIDC binds issuer and subject with state, nonce and PKCE validation; linking an existing account requires authenticated explicit confirmation. Use server-revocable sessions, CSRF protection for cookie-authenticated mutations, key expiry/revocation and tenant-scoped role/service-key administration. Logout/revocation affects subsequent requests, not only a browser cookie.

`auth.SecretResolver` owns the concrete operator-configured environment-backed reference bindings. Inference, source adapters and MCP resolve by tenant, integration purpose and exact approved origin(s); none may turn a public `credential_ref` into `os.Getenv` or inherit an unrelated SDK default key. No second secret backend or public credential-provisioning product is introduced.

Source identity is `(tenant, connection, source kind, source-native object ID)`, not an unqualified filename, title, URL or source-wide object ID. Preserve native revision when supplied and a distinct monotonic local observation/content revision when not. GitHub file paths identify logical files within their configured repository/connection; commit/blob IDs belong to immutable revisions and commit-pinned provenance. Identical bytes observed after A→B→A must not collapse a new source transition into an old job or hide a deletion/revocation.

Separate immutable original/artifact versions, parsed blocks, chunk/profile versions, generated results, source-native provenance, effective grants, membership snapshots and index/publication generations. Generated content is never relabeled as original evidence. Store source timestamps, synchronization/access status and location evidence without presenting unavailable revisions or anchors as precise.

Filesystem writes stream to a private temporary file and enforce limits. `Begin` persists a writing row with lease/fence before creating bytes. Finalization and reconciliation lock/check that same row: verify the live writer before rename/fsync/ready commit; invalidate an expired writer before reaping its bytes. An active writer is never an orphan, including during another process's startup. Never hold a database transaction over an incoming upload stream or acknowledge input before durable bytes and ready metadata exist. Reconcile only application-owned files, not caller-supplied paths. Workers share the configured durable root; scratch directories are private, bounded and removed after cancellation/failure.

Reconciliation tombstones a confirmed missing final artifact with `tombstone_reason=missing_final_bytes`; it does not invent an unsupported state or block startup after handling that inconsistency. Filesystem permission errors or an unavailable/unverified data root are errors, not proof that artifacts are missing.

The artifact boundary is `Store.Begin/Finalize/Read/Delete/Reconcile` with opaque `artifacts.Ref`; no alternate Create/OpenReader interface. Source DTOs store opaque artifact identifiers without importing the artifact service back into source. Keep the package graph acyclic.

## Authorization and processing policy

Source-native effective grants and principal/group membership are server-maintained revision-qualified data, separate from content snapshots. Authorization selects a complete current snapshot; incomplete replacements cannot become authoritative. Applicable current deny grants override allow grants. Unknown or unusably stale required access data denies access. Only a complete snapshot may remove unseen objects/grants. Connection disablement, recorded revocation, identity changes and tombstones block subsequent affected reads before index cleanup finishes.

Notion is the deliberate exception to native sharing parity: a publisher with verified access selects a page/subtree and explicitly assigns Enclava audiences. Store and display `published_audience` authorization mode. A page reference/link does not grant authority to ingest a separately protected linked object. Upstream publisher-access loss and unpublishing stop serving affected material. Opening the native Notion page still depends on the reader's separate Notion access.

Uploads and generated outputs have explicit owner/audience grants; source connector credentials do not become end-user authority. Authorize source listing, retrieval candidates, expanded context, retained originals, snippets, citations, results, conversation replay, tool output and export. Unknown and forbidden object/reference IDs have the same public outcome. Never reveal titles, snippets, counts or locations before authorization.

Persist server-owned processing restrictions on connected sources, uploads and derived artifacts. An execution's allowed destinations/capabilities are the intersection of tenant policy, actor authority, endpoint capability/assurance and every referenced input's restrictions. Request options may narrow this set, never widen it. Derivatives and conversations retain the restrictions and source references of their inputs. No policy is inferred reliably from arbitrary pasted text; do not claim automatic classification or declassification.

## Inference, accounting and concurrency

Endpoint records are tenant-scoped and bind protocol, capability, base origin, credential reference and real assurance state. Administrative configuration must explicitly authorize a private endpoint; reject arbitrary user URLs, credential redirection and DNS/redirect origin changes. Do not infer that local means confidential or that an ordinary TLS endpoint is an attested enclave. Required confidential verification failing means no dispatch.

All model calls use one `inference` executor: public chat/embeddings/Responses, agents, document extraction/vision, query rewriting, embedding/indexing and any bounded section selection. No direct-provider escape in dashboard handlers, background jobs or helpers. The executor takes a validated principal, operation/capability, immutable input references and bounded request; it resolves policy server-side and returns a request/attempt identity with observable usage/outcome.

Support public `/v1/models`, `/v1/models/{id}`, `/v1/chat/completions`, `/v1/embeddings` and the selected Responses operations (create/stream, retrieve, delete, cancel, input items, input-token calculation and compact). Preserve supported OpenAI wire/event/tool-call formats. Document and explicitly reject unsupported products/extensions; remove unrestricted passthrough and legacy duplicate aliases. A provider lacking an operation returns a capability error, not a fabricated response or local substitute.

Responses IDs and other retained upstream references bind local owner/tenant, endpoint origin, input restrictions and upstream ID. Resolve `previous_response_id` and nested resource/tool/file/image references under that binding; never route a bare shared-provider resource ID supplied by another caller. Inspect nested destinations and tools, not only the top-level model field. If a requested resource/tool shape cannot be authorized or safely priced, reject it before dispatch. Cancel/delete remain available when ordinary inference budget is exhausted.

Use exact money arithmetic with persisted integer units and checked bounds, not float accumulation. Prices are keyed by explicit billable unit: input, output, cached input and supported advertised units. Snapshot all selected rational rates as `{rates:[{unit,rate_micros,unit_quantity}],currency,rounding_rule}` and reserve an enforceable upper bound atomically before a priced attempt; missing required rates or mixed currencies deny dispatch, with no implicit free units or FX. Cached input and uncached input settle disjointly. Tenant and billing-subject reservations are authoritative in PostgreSQL across processes. Record raw per-kind actual usage without clipping, settle once using the original snapshot and preserve any overrun. Unknown upstream outcomes retain liability and are not automatically retried, refunded or replayed. Do not hold a database transaction during an upstream call.

Persist reserved per-kind unit quantities as well as the monetary ceiling and immutable rate snapshot. Token liability cannot be reconstructed from money when rates differ or are zero. Amount budgets bind a currency and reject incompatible reservations. Inside the locked admission transaction, existing settled plus held/unknown liability plus the proposed checked bound must fit every applicable limit; account for overflow and test a request larger than the remaining allowance.

Bound active upstream work, queued requests, queued bytes, streams and internal fan-out. Hold a permit until response/stream bodies close; propagate disconnect, timeout and cancellation to child work and release resources exactly once. Do not retry a possibly accepted mutation or a partially observed stream on another endpoint. Per-process capacity and database-enforced tenant/accounting limits are distinct; state and test that distinction. Verify overload fairness/cancellation and shared accounting with two application processes, not just a single goroutine test.

## Jobs and publication

Job creation stores immutable inputs, submitting principal/policy, operation and idempotency identity before returning a job ID. Bind replay identity to the tenant, operation and submitting actor/delegation/credential/billing context; another owner cannot receive or reuse the first owner's job. Reusing that identity with different inputs/policy/revisions is a conflict. Use durable leases with fencing: an expired/stale worker cannot publish progress/results or resurrect deleted/cancelled work. Distinguish queued, running, succeeded, failed, cancelled and unknown-outcome states; bounded classified retry applies only where replay is safe. Cancellation is not proof that upstream side effects never happened.

Content/index replacement stages a new immutable generation and publishes only when all required artifacts, current authorization and index writes are ready. Failure keeps the last still-authorized generation usable; it never makes revoked content readable. Reprocessing is distinct from a source edit. Recheck source and access revisions at each publication/attachment boundary. Tombstones hide affected data immediately; durable cleanup is fenced/idempotent and cannot delete a newer generation.

## Parsing, chunking and standalone processing

Supported text/Markdown/HTML/CSV/JSON, DOCX, PDF and image inputs must be processed with real format-aware code/tools. Replace printable-byte/regex PDF fallbacks. Validate bytes as well as declared MIME, expanded archives, pages/pixels, output size and deadlines. Poppler/Tesseract run without a shell in private work directories, with bounded process trees/output, no network and no access to application secrets or unrelated artifacts. Use an existing Linux isolation primitive/tool rather than inventing a sandbox. Required tools/assets missing means an explicit failure, not fake success or a hidden Python fallback.

Parsing emits ordered stable blocks with document hierarchy, page/paragraph/table/message/code location where actually available, and immutable extracted text. A source span identifies its block plus UTF-8 byte range; layout locators retain page/box/table/clause metadata where supported. Do not manufacture headings, page numbers, symbols, coordinates or confidence. Byte offsets refer to extracted block text, not imaginary offsets inside a compressed PDF/DOCX file.

Versioned profiles control boundaries, size, overlap, parent inclusion and table handling. Label size units truthfully; do not present character counts as token counts. Legal profiles preserve clauses, subsections, definitions and referenced exception/footnote/table context without inventing a universal legal ontology. Chat preserves message/thread authorship, edits and timestamps; structured documents preserve headings/tables; code preserves actual file/line and available symbol locations. Preview shows the actual blocks/chunks/spans and warnings that indexing will use. Changing a profile creates a new processing version, never silently mutates published evidence.

`source.ChunkProfile.ID` identifies one immutable version row; `ProfileID` identifies the family and `Version` is monotonic within it. Use `PRIMARY KEY (tenant_id,id)` and `UNIQUE (tenant_id,profile_id,version)`. Persistent processing/collection/chunk references use `chunk_profile_version_id`, a foreign key to the immutable row, never a floating family ID. The preview HTTP surface persists a bounded new-file upload and exposes owned status/result/cancel directly through the shared artifact/jobs services, without requiring search or inference.

Structured output is validated locally with a maintained implementation of the selected JSON Schema dialect. Support local references without HTTP/filesystem schema fetching; reject unsupported dialect/features explicitly. Preserve exact numeric values rather than round-tripping them through floats. Valid schema output is not evidence of factual correctness.

Extraction/image jobs are asynchronous, version their input/task/schema/prompt/model/results and use the shared inference executor. Durable status/results/cancel/delete are owner-authorized and restart-safe. Expose original evidence locations only when they exist, plus generated output/errors and actual usage. Do not fabricate OCR certainty or bounding boxes for an unconstrained model answer. An authorized explicit import can attach a generated result to knowledge with inherited restrictions; there is no automatic indexing. These APIs/screens work with Qdrant absent.

## Connectors and search

Each of Slack, Teams, GitHub, Notion and Google Drive gets a real source adapter, bounded pagination/delta handling, qualified identity, native URLs, retained locations and explicit content/grant/membership completeness. Preserve edits/deletes, checkpoint only durable progress and resume safely after interruption. Rate-limit/retry handling is bounded and respects provider semantics. Never replace an entire conversation with only its latest incremental page. Use current primary API documentation, not stale assumptions copied from another connector.

Raw adapter observations carry native IDs/revisions; only durable orchestration resolves `source.ObjectRef` and allocates its monotonic local sequence. It finalizes adapter bytes through the shared artifact store, persists their references and durably enqueues ingestion before advancing a content checkpoint. Independently fenced access/membership consumers update canonical source authorization; composition registers every consuming worker operation. Ingestion converts native message/thread, Notion block/table and Sheets tab/cell metadata into canonical source documents/blocks/locators; actual file bytes use the shared file parser. Use canonical source-kind values, including `google_drive`. Schedule/checkpoint content, access and membership independently so a long crawl cannot block required permission refresh. A timestamp tail is not a deletion/edit feed: Slack requires complete reconciliation in addition to new-message polling.

Keep connector boundaries compatible with real permissions: source identities/groups map through an explicit verified tenant-and-connection-scoped binding/revocation operation in source management; unknown mappings do not become company-wide access and email equality is not proof. Google Drive inheritance/shared-drive/restriction semantics and Teams standard/private/shared channel or chat membership require explicit handling, including effective direct/indirect shared-channel membership. GitHub repository read grants come from effective repository collaborators, not a union with every organization member. Source settings/UI expose supported scope, bindings and permission freshness; do not claim unavailable parity.

Connector configuration selects a server-approved `credential_ref` bound to tenant, source kind and provider origin, not an arbitrary environment-variable name or another tenant's credential. Operator-owned environment-backed bindings may supply secrets. Discovery/configuration/status/errors must not expose secret values. Drive link-only discovery and copy/download restrictions are not silently converted into company-wide grants or a second published-audience exception; where the required native permission cannot be established/enforced, fail closed and report the limitation.

Knowledge HTTP routes expose explicit stored-result import through the same authorized import service used for uploads. Consume immutable core result/artifact records rather than a phase-3 runtime API; preserve generated provenance and inherited restrictions. No automatic indexing of processing results.

Use Qdrant native BM25 sparse vectors plus dense embeddings and the query API with one explicitly configured RRF rule. Confirm the exact API features against the supported Qdrant version; existing 1.15.5 configuration cannot silently assume newer weighted-fusion fields. Apply tenant/source-generation/access candidate filters to both branches and authoritative authorization again before returning or expanding any result. No separate lexical engine or whole-corpus lexical rebuild on each update.

Unrephrased direct lexical/dense retrieval is always available. Bounded query expansion/section selection uses the same authorized, priced executor and remains optional; failure cannot silently broaden access or force unavailable inference for lexical-only search. Merge duplicates only for identical source-version spans; preserve similarly worded but distinct legal clauses/exceptions. Reconstruct bounded authorized parent/adjacent context without overflowing the model budget.

Models return evidence IDs, not authoritative URLs. Resolve IDs on the server to current authorized source version, native link, retained copy and real locations; fabricated, stale or forbidden IDs are rejected consistently. Reauthorize at display/download, agent hand-off and conversation reuse. Source deletion or revocation must remove affected prior text from reusable context, not merely hide a citation badge.

## Agents and product UI

Build on existing chatbot/prompt/conversation concepts. An assistant selects approved model/routes, instructions, permitted collections and tools; actual per-run authority is still intersected with the caller and source restrictions. Persist bounded runs/tool attempts, errors/cancellation and evidence/restrictions, not just a fake chat response.

Outbound MCP is administrator-approved Streamable HTTP servers and explicitly approved tool names/schemas using the maintained Go MCP SDK. Bind credentials to origin/tenant; bound discovery, redirects, response bytes, calls, time and output. Tool annotations are untrusted hints, not authorization or idempotency guarantees. A changed/unapproved tool schema is not silently enabled. No stdio/arbitrary-code tools. Tool results inherit input restrictions; unknown side effects are not retried automatically. Built-in extraction returns the durable job identity/status rather than secretly waiting synchronously.

Use existing embedded templates and static assets, with feature-local JavaScript/CSS where parallel ownership needs it. Show actual route assurance/capabilities, usage/reservations, source/access/sync status, previewed boundaries, source locations and processing errors. Enforce access server-side, escape untrusted content and preserve keyboard/focus/label/error semantics. Do not show an implemented-looking page for a missing endpoint or mark an unavailable integration healthy.

## Verification contract

Executable plans name real package/API checks and consumer-visible regression cases. Shared test fixtures isolate PostgreSQL schemas, artifact roots and Qdrant collections; they must not reset a user database or share mutable tenant data across tests. Fakes cover deterministic protocol/error cases, not claims about real provider permissions, attestation, parser behavior or retrieval quality.

Parallel writers finish before the integration owner runs shared-package builds/tests/formatters. The listed commands specify required checks, not permission to race them against another plan still editing that package. Serialize shared composition/docs mutations and run the integrated checks afterward.

Run actual application/worker paths with PostgreSQL, Qdrant where needed, native processors, an authorized source workspace and configured inference/IdP/MCP endpoints. Tests that skip for missing credentials do not prove integration success. Report exactly which prerequisites were exercised. For UI, open the actual application and check keyboard interaction plus narrow/desktop views. Update affected application docs only after runtime proof; no new deployment or reporting workstream.
